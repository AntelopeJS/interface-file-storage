This page is for storage backend authors. Application authors can start with [file operations](./2.file-operations.md), which covers their authorization, admission, and cancellation duties.

## Implement the promotion hook

A provider implements `internal.promoteFile`, with this signature:

```ts
import type { PromoteFileResponse } from "@antelopejs/interface-file-storage";

type PromoteFileHandler = (
  resourceKey: string,
  storage?: string,
) => Promise<PromoteFileResponse>;
```

`PromoteFile` forwards to this hook and has no fallback to `MoveFile` plus `FileExists`. An adapter must implement the hook to support promotion.

## Publish a complete object

| Provider obligation                                                            | Why it matters                                                      |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| Publish bytes, metadata, visibility, and trusted origin together               | A reader must not see an incomplete result.                         |
| Make local metadata publication recoverable                                    | A rename of the bytes plus a separate metadata write is not enough. |
| Reject or isolate upload-controlled origin fields                              | Client metadata must not forge promotion provenance.                |
| Bind trusted provenance to the source and canonical destination across retries | Matching retries reach the same complete result.                    |
| Enforce conditional publication or throw                                       | A provider must never silently overwrite a destination.             |

Publish to the key that `stripStagingPrefix` returns, in the same storage. Remove the source only after you verify the final publication. A complete matching destination lets a retry succeed even when the source is already gone. An unrelated or unverifiably incomplete destination throws `FileConflictError`. A missing source without a committed destination throws `FileNotFoundError`. An unknown outcome must throw, not return an assumed success.

For private uploads, enforce private access to both the staged and the final bytes. Signed URLs over storage that anyone can read do not make files private. Promotion has no cancellation fence. Delayed work may publish an orphan, and the application must never admit it into a cancelled record.

## Validate an adapter

Run the shared [provider conformance suite](./1.introduction.md#provider-conformance-tests) with a disposable backend. Keep the provider's own fault, signature, routing, and lifecycle tests in the adapter. Passing the interface's forwarding unit tests does not show that an adapter publishes complete objects safely.
